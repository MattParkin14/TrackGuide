# TrackGuide

A web app that recommends iRacing tracks worth buying, based on the cars you race. Pick your cars and either:

- **Tracks to buy** — see a sorted list of tracks ranked by most-weeks-raceable, popularity, or historical recurrence. Tracks already in iRacing's base package are flagged so you don't double-count them.
- **Series for my cars** — see every series your cars are eligible for, with this season's track lineup and how many of those tracks you'd need to buy.

**Stack**: Vite + React + TypeScript + Tailwind. Static SPA served by a Cloudflare Worker. All recommendation logic runs in the browser against a pre-built JSON dataset.

## Local development

```bash
npm install
npm run dev
```

Open the URL Vite prints (typically http://localhost:5173).

## Build & local preview

```bash

```

`npm run preview` runs the built assets through `wrangler dev`, which is closer to the production Cloudflare Workers runtime than `vite preview` would be.

## Data pipeline

The app loads a single static dataset from `public/data/dataset.json`. It currently contains:

- **Catalog**: 138 cars and 147 tracks (307 configs) currently appearing in any iRacing series schedule.
- **Schedules**: full week-by-week schedule for the current season plus four prior seasons (5 quarters total).
- **Base-package flag**: tracks fully included in iRacing's base content are marked `isFree: true` so the UI can highlight them.

That file is regenerated by:

```bash
npm run sync-data
```

The script (`scripts/sync-from-upstream.mjs`) clones the upstream repo [`adrianulima/my-racing-planner`](https://github.com/adrianulima/my-racing-planner) (MIT-licensed; the maintainer fetches official iRacing data each season and commits the result), checks out one pinned commit per season, transforms the data into our `Dataset` shape, and writes `public/data/dataset.json`. The upstream mirror is kept under `.upstream/` (gitignored) and only re-fetched when the script runs.

To pick up a new iRacing season:

1. Find the upstream commit where the new season's data was first published (look for a commit message like *"Update with 2026 season 3"* in `git log -- src/ir-data/`).
2. Add an entry to the `SEASONS` array at the top of `scripts/sync-from-upstream.mjs`, set its `current: true`, and flip the previous current season's flag to false.
3. Run `npm run sync-data` and commit the regenerated `dataset.json`.

The transform handles a few oddities:

- **Track configs**: upstream stores each config as a flat row; we group rows that share the same parent name into our `Track { configs[] }` shape.
- **Categories**: car/series categories use the granular split (`sports_car`, `formula_car`, `oval`, `dirt_oval`, `dirt_road`); track categories use the iRacing-package split (`road`, `oval`, `dirt_oval`, `dirt_road`) since iRacing licenses tracks per package, not per car class.
- **Retired content**: weeks that reference a track or car no longer in the current catalog are dropped — historical schedules sometimes use ids that have since been retired.
- **Orphans**: cars and tracks that don't appear in any series across the 5-season window are filtered out so the selector only shows actionable choices.
- **Popularity**: until we have real participation data, popularity is a crude heuristic derived from license class and whether the series is fixed-setup. It's good enough to break ties; don't read too much into the absolute scores.

## Deploying to Cloudflare Workers

The project is wired to deploy as a **Cloudflare Worker serving static assets** (the modern equivalent of Pages for SPA-only sites). Configuration lives in `wrangler.jsonc`:

- `assets.not_found_handling = "single-page-application"` — any unknown route falls back to `index.html`, which is what an SPA needs.
- `compatibility_flags = ["nodejs_compat"]` — enabled in case we ever add a Worker function.
- `observability.enabled = true` — turns on Workers Logs in the CF dashboard.

Two ways to deploy:

**1. From your machine** (one-off or for testing)

```bash
npx wrangler login          # first time only
npm run deploy              # = npm run build && wrangler deploy
```

The first deploy provisions a `*.workers.dev` subdomain (typically `trackguide.<your-subdomain>.workers.dev`).

**2. Connect-to-Git via the Cloudflare dashboard** (recommended once you're happy with the local deploy)

1. Cloudflare → **Workers & Pages → Create → Workers → Import a repository** → pick `MattParkin14/TrackGuide`.
2. CF auto-detects `wrangler.jsonc`. Confirm:
   - Build command: `npm run build`
   - Deploy command: `npx wrangler deploy` (or leave the default if CF prefills it)
   - Production branch: whatever you want CF to track (typically `main` once you've merged)
3. Save and deploy. CF will auto-deploy on every push to that branch.

**Custom domain**: in the Worker's settings → **Triggers → Custom Domains → Add Custom Domain**. You need the apex or subdomain to be on a CF-managed zone; CF wires the routes automatically.

No backend code or env vars are required for the site itself. The data-sync script (`npm run sync-data`) runs locally or in CI to update `public/data/dataset.json`; the Worker only serves static assets.

## Project layout

```
wrangler.jsonc                   Cloudflare Workers config (SPA fallback, observability).
vite.config.ts                   Vite config; uses @cloudflare/vite-plugin for dev parity.
public/data/dataset.json         Canonical app data. ~2 MB raw, ~60 KB gzipped.
scripts/sync-from-upstream.mjs   Regenerates dataset.json from the upstream community repo.
src/types.ts                     Domain types (Car, Track, Series, Season, Dataset).
src/lib/dataset.ts               Fetches dataset.json at runtime.
src/lib/recommend.ts             Track ranking engine — three RankModes.
src/lib/series-finder.ts         "Which series use my cars?" lookup with per-series track lineup.
src/components/CarSelector.tsx   Multi-select car picker with search + category filter.
src/components/ResultsList.tsx   Ranked track list; flags base-package tracks with a green badge.
src/components/SeriesList.tsx    Series-for-my-cars view; per-series free vs paid track summary.
src/App.tsx                      Top-level layout, tab switcher (Tracks vs Series), state.
```

## Roadmap

- **Phase 1** *(done)*: scaffold, hand-curated seed data, engine, UI, deploy target wired (Cloudflare Workers serving static assets).
- **Phase 2** *(done)*: real schedule pipeline from `adrianulima/my-racing-planner` covering current season + 4 prior seasons. No iRacing login required.
- **Phase 2.1** *(done)*: base-package track marker; "Series for my cars" view alongside the recommendations tab.
- **Phase 3**: extend backfill to 8+ seasons. Will likely require per-era adapters as the upstream data shape has evolved.
- **Phase 4**: real series-participation / SOF data (replace the popularity heuristic). Probably needs an authenticated iRacing data pull, even if just done quarterly by a maintainer.
- **Phase 5**: filters (license class, oval/road/dirt), "exclude already-owned tracks" toggle, mobile polish, share-link state.
